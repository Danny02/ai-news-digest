# AI news digest — 2026-08-03

## Qwen 3.8 is coming open-weights, and it is competitive

- Qwen3.8-Max (2.4T params) goes **open-weights next week**, along with the
  small Qwen3.8-27B. A frontier-tier coding model becomes self-hostable.
- Qwen3.8-27B runs locally on **17GB RAM/VRAM** (per UnslothAI); several people
  call it a godsend for the 24GB class — local autonomous coding without a
  cloud model.
- Positioned as a real option: **#4 on the Frontend Code Arena** (1,668),
  trailing only Opus 5 (Max) and Kimi K3. One tester put it on par with Opus 5,
  Kimi K3 and GPT 5.6 Sol on the same prompt.

## Opus 5: several people are souring on it, and there are fixes

- Several independent reports this week: Opus 5 goes off-track, forgets, and
  wants approval constantly. The refrain is "the more I use it, the worse I
  like it" (kimmonismus, MangoSweet78, mattpocockuk).
- Concrete fixes people are using: tell it to write in **ASD-STE100** to kill
  the verbose "load bearing / it earns X" slop (dexhorthy); revive a
  `/zoom-out` skill to force it to summarise when it rambles (mattpocockuk).
- If you had a "technical writing" instruction, this is the week to keep it.

## Harness engineering is the week's theme

- A CS paper now frames **harness engineering as the primary determinant of
  agent reliability** (a seven-layer architecture unifying sandboxes, tool
  protocols and context) — theory catching up to how agents actually run.
- GitHub's own framing: "there is no secret, there is just the harness".
- Lilian Weng (OpenAI) wrote the sharp breakdown of harness design, workflow
  automation and file-system memory.
- Vocabulary to fix debugging: **LOOP vs GRAPH vs HARNESS** are three
  different layers, not the same thing (elune0x).
- DeepSeek is building a dedicated coding agent on a new Harness framework for
  autonomous software engineering.

## Context: the long-session decay, and a fix

- "Context window dementia": killing a productive long session because Claude
  starts losing the thread (g_br_l, 9.3k likes).
- Claude gets measurably more stubborn as the context fills — argues for
  compacting earlier, not later (NateSilver538).
- A workable pattern: **four flat markdown files, zero databases** for agent
  memory (alex_prompter) — readable and searchable, no vector store.

## Tools and skills worth a look

- **Codex**: one config change makes it use the multiple-choice tool outside
  plan mode — "feels 100x better" (davis7).
- **Claude Connectors** (gmail, calendar, Slack) also work inside Claude Code,
  including in Artifacts — easy to miss (trq212).
- **Taste Skill** (open-source): improves agent-generated UI, works across
  Claude Code, Codex, Cursor and more (rammcodes).
- **/watch-video** (coreyhainesco): transcript + frames + vision pass over any
  recording.
- A near-zero-cost pattern: chain ImageGen then img2threejs skills in Codex
  (NicolasZu).
- Skills still **do not transfer** between Codex and GPT Work — worth knowing
  before you invest in one tool's ecosystem (rileybrown).
- Anthropic published a **per-model prompting playbook** for the whole current
  Claude lineup (shmidtqq).

## GPT-5.6: the pricing signal and a caution

  misleading: **Luna is much cheaper** than Sol but not equivalent.
- Same caution: not recommended for serious production code yet — a refactor
  that both Sol Ultra and Opus 5 Ultracode struggled with (diegohaz).
